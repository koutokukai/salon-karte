## 1. ターゲットの再定義（最重要）

**狙うのは「駆け出し・自宅サロン・1店舗個人事業主」。ここを1件もこぼさない。**

複数店舗・大型店は**狙わない**。理由：
- 既に独自のカルテ運用を持っており、移行しない
- 「多少便利」程度では現状維持に負ける

ただし**2名以上の店舗は狙う**。理由は便利さではなく、後述の「スタッフ独立による顧客離脱」への恐怖（→ 6章）。

### 移行の壁は「機能」では越えられない

紙カルテ相手でも勝てない。現状維持のコストはゼロ、移行のコストは有限だから。
人間は変化を拒む。したがって**機能で勝とうとせず、移行コスト側をゼロに近づける**。

**打破策4本：**

| # | 施策 | 狙い |
|---|---|---|
| 1 | **過去分を入力させない** — 紙カルテを写真で撮って貼るだけで顧客登録完了 | 移行作業そのものを消す。紙も捨てさせない、二重運用を許す |
| 2 | **既存客は2回目以降3タップ** — 「前回をコピー」（実装済み） | 紙より速い状態を作る |
| 3 | **紙では絶対にできない1つを持つ** — 前回来店から◯日経った顧客の一覧 | カルテを「記録」から**集客装置**に変える。唯一の移行動機 |
| 4 | **入力代行**（ひろぽん） | 初回◯人まではこちらが入力。クロージング材料 |

### 駆け出し・自宅サロンに刺さる理由（困りごと解決では売れない）

顧客が少ない人は紙で困っていない。売れる理由は別にある。
- これから増える客を**最初から貯められる**（後で入力する地獄の回避）
- **プロに見える** — 自宅サロンでもタブレットでカルテを出すと信頼が上がる。価格より効く可能性がある
- 3ヶ月無料で始められる

## 2. トライアル：3ヶ月無料（無料プランは作らない）

**恒久無料プランは廃止。期間限定に統一する。**
狙いは「顧客が溜まると辞めにくくなる」構造を作ること。

### なぜ1ヶ月では足りないか（施術周期からの計算）

| 業種 | 施術周期 | 1ヶ月での再来店 | 3ヶ月での再来店 |
|---|---|---|---|
| ネイル | 3〜4週 | **1回** | 3回 |
| マツエク | 3週 | 1回 | 4回 |
| ヘア | 6〜8週 | **0回** | 1〜2回 |
| リラク | 2週 | 2回 | 6回 |

**1ヶ月ではヘアサロンが1回も再来店しない** = 「前回のカラー配合をそのまま再現できた」という
我々の核心価値が発動する前に judgment されてしまう。よって **3ヶ月で確定**。

ヘアは3ヶ月でも1〜2回転だが、1日の客数が多くカルテ件数が溜まる（個人サロンで月20〜40人 →
3ヶ月で60〜120件）。この蓄積自体がスイッチングコストになる。

### トライアルの条件（守る）
- **クレカ登録を最初に求めない**（求めると開始率が落ちる）
- 終了時に**こちらから**「今やめてもCSVで全部持ち出せます」と言う。**引き止めない方が残る**

## 3. 価格（v3・確定案）

**課金単位は「人数」ではなく「アカウント数」。**
理由：①人数申告は検証できないがアカウント数はシステムが数えられる ②スタッフが増えた日に
自動で増収し営業が介在しない ③「基本2,980円、1人増えるごとに500円」で説明が1行で済む。

| プラン | アカウント数 | 月額 |
|---|---|---|
| トライアル | 全プラン共通 | **3ヶ月無料**（クレカ登録なし） |
| 個人 | 1 | **980円** |
| **店舗導入パッケージ** | **3込み** | **2,980円** |
| 追加アカウント | 1つにつき | **+500円** |
| 初期費用 | — | **0円** |

実額：3名 2,980円／5名 3,980円／8名 5,480円／10名 6,480円
→ **10名規模でも競合オールイン（9,800円前後）を下回る。**

### 「3倍のジャンプ」という見立ては誤り（2026-09-04 修正）
個人980円 → 店舗2,980円を「値上げのジャンプ」と捉えたのは間違いだった。

- 店舗導入パッケージは**自宅サロンの人が昇格する商品ではない**。最初から店舗の人が契約する別商品
- 個人プランの利用者にとっては、**2人目を雇うタイミングで切り替えるもの**。
  つまり価格が上がるのは「雇用が発生した」という事業の段階変化に対応しており、不自然な跳ね上がりではない
- 支払う理由も違う。個人は「自分の記録」、店舗は「**アカウントを分けて管理できること**」に払う

### アカウント共有は禁止しない
1アカウントを4人で使ってもよい。禁止しても検知できないし、禁止は敵対的で関係を壊す。
**代わりに、分けた方が得になる状態を作る。**

| 1アカウントを共有すると | アカウントを分けると |
|---|---|
| ログインは1端末のみ。誰かが入ると他は落ちる | 各自のスマホで同時に使える |
| 担当スタッフ名を毎回手入力 | 担当が自動で入る（入力が1つ減る） |
| 全員の顧客が1つの一覧に混ざる | 自分の担当だけが並ぶ |
| 誰が触ったか分からない | 操作ログが残る＝**「自分は触っていない」を証明できる**（スタッフ側の利点） |
| 指名売上・リピート率が出せない | スタッフ個人の成績が自動で出る。**スタッフ自身が欲しがる** |
| 顧客からのチャットが誰宛か分からない | 担当に届く |
| 退職時に引き継ぎ作業が発生する | アカウント停止だけで済む |
| オーナーが全体を把握できない | PCで全員分を横断管理できる |

**共有時の不便は「意図的に不便にする」のではなく、分けた場合の利点が自然に効かないだけ**という形にする。
罰を与える設計にすると、共有している店は課金ではなく解約を選ぶ。

## 4. Webアプリであることを全面に押し出す

競合5社のうち**Webのみは EyeRec だけ**（月2,480円で成立している＝先行事例）。
他はネイティブ。そこに明確な弱点がある。

| 競合の弱点 | 我々の訴求 |
|---|---|
| LiME：**iOS↔Androidのデータ移行不可** | **「機種変更してもカルテは消えません」**（営業トークの一言目） |
| カルテナ：**端末内にデータ保存** | 端末が壊れても・機種変しても残る |
| Bionly：**iPad専用** | iPhone / Android / PC / タブレット、全部同じ |
| ネイティブ全般：インストール・審査 | **URLを送れば即使える**（我々の営業はこれでしか成立しない） |
| ネイティブ全般：端末ごとにデータが閉じる | **複数端末で同時に見られる**（→ 店舗の一括管理） |

### ただし正面から潰すべき弱点：オフライン
カルテナは「オフラインで全機能動作」を売りにしている。地下・半地下の店舗は電波が入らない。
段階的に対応する：
1. **ホーム画面に追加＋アイコン（PWA化）** — 半日。「アプリじゃないんでしょ？」を消す
2. **閲覧のオフライン対応** — 前回カルテが電波なしで見られる。1〜2日
3. 入力のオフライン対応 — 端末に貯めて後で同期。重いので要望が出てから

## 5. 個別対応の方針（コードは店ごとに分けない）

店舗ごとにコードを分けると10店舗で保守が破綻する。**契約が増えるほど動けなくなるため受けない。**
代わりに**設定で吸収する**。

| できる（設定機能として実装する） | やらない |
|---|---|
| カルテ項目の表示・非表示・並び替え | ボタン配置を店ごとに変える |
| **独自項目の追加**（店が自分で作れる） | 画面構成そのものの変更 |
| よく使うメニュー・薬剤のプリセット登録 | 店専用の機能追加 |
| 店名・ロゴ・テーマ色 | — |

**「独自項目を店が自分で追加できる」だけで個別要望の9割を吸収できる。** 全店共通機能なので保守は増えない。

**【サレオツ】ボタン配置だけは変えさせない。** 押す位置が変わると誤操作が増える。
これはこの設計の出発点であり、店ごとの好みより現場の安全を優先する。

Phase 3 の「反応があった相手に即座に改造」も**コード改造ではなく設定で出す**。その方が速い（数分）。

## 6. 店舗導入パッケージ ＝ 顧客資産の防衛

**売りは便利さではない。経営者の恐怖に応える商品である。**

> 人に客がつく。スタッフが突然独立すると、多くの客が離脱する。

**経営者への一言：「スタッフが辞めても、カルテは店に残ります」**

### 必要な機能（→ 設計は `docs/80-edison-staff-design.md`）
1. **スタッフ個別アカウント＋権限**（オーナー／スタッフ）
2. **操作ログ** — 誰が・いつ・何を・どう触ったか
3. **店のPCで一括管理** — オーナーが全スタッフ・全顧客・全ログを1画面で

### ログで本当に効くのは「編集」ではなく「閲覧・持ち出し」
独立時に実際に起きるのは**辞める直前に顧客リストを大量に見る／エクスポートする**こと。
編集履歴だけではこの動きを捕まえられない。

| 記録対象 | 理由 |
|---|---|
| カルテ・顧客の作成／編集（**変更前後の差分**） | 「どう触ったか」の本体 |
| **顧客一覧の大量閲覧** | 退職前の名簿収集の兆候 |
| **CSVエクスポート** | 持ち出しそのもの。全件必ず記録 |
| ログイン・ログイン失敗 | アカウント共有の検知 |

### 運用上の判断
- スタッフは**全顧客を見られるが、すべて記録される**。サロンは担当交代・ヘルプが日常であり、
  見えないと業務が回らない。制限したいオーナー向けに「自分の担当のみ」設定も用意する
- 退職時は**アカウント停止のみ。カルテは店舗に残る**
